# 지원서 AI 활용 경험

저는 Codex와 Claude를 정답 생성기보다 ‘가설을 빠르게 만들고, 틀린 주장을 찾아내며, 결과를 재현 가능하게 만드는 검증 파트너’로 활용했습니다.

가장 대표적인 경험은 UCI SECOM 반도체 공정 데이터 1,567건·센서 590개를 분석한 프로젝트입니다. 첫 Random Forest는 정확도 93.3%였지만, 별도 보류 데이터의 불량 21건을 한 건도 잡지 못했습니다. AI와 함께 원인 후보와 실험 코드를 만들되, 저는 평가 기준을 Recall·PR-AUC로 바꾸고 데이터 분할 이후의 전처리·특성 선택·임계값 결정을 학습 데이터 안에서만 수행하도록 재검증했습니다. 5-fold OOF 예측에서 정한 임계값 0.0717을 손대지 않은 314건에 적용하자 TP 19, FN 2, FP 117로 Recall 90.5%, Precision 14.0%, 재검사율 43.3%, PR-AUC 0.238이었습니다. 이는 ‘좋은 모델’의 선언이 아니라 미탐 감소와 재검사 증가를 함께 보여주는 운영 선택지입니다. 더 중요하게는, 처음 주장했던 ‘상위 80개 센서가 전체보다 우수하다’는 결과가 특성 선택을 fold 내부로 옮긴 3회 반복 교차검증에서 재현되지 않았습니다(80개 0.137, 전체 0.168). 저는 유리한 수치를 남기지 않고 해당 주장을 철회했습니다.

두 번째로 Qwen2.5-0.5B LoRA와 RAG를 8개 합성 Q&A·5개 질문으로 비교했습니다. RAG가 외부 문서의 CUDA 12.4를 회수하고 문서를 13.0으로 바꾸자 반영했지만, 일부 질문이 학습·검색 문서와 동일해 일반 성능을 증명하지 못한다는 평가 누수를 발견했습니다. 따라서 “RAG가 우월하다”가 아니라, 이 제한된 exact-match 탐색에서 최신 사실 회수 가능성만 확인했다고 결론을 낮췄습니다.

마지막으로 LangChain·Chroma·LangGraph로 13개 원본 단위, 60개 chunk를 검색하는 학습 코치를 구현했습니다. 검색·퀴즈 도구 선택과 thread별 메모리를 실행했지만 실제 사용자 활용 성과는 없습니다. 재검토 중 평가 질문이 색인된 Day 3 보고서 안에도 들어 있어, 외부 질문에 ‘근거 없음’ 대신 자기 보고서를 검색하는 오염을 찾았습니다. 지식 corpus와 평가·보고서를 분리하는 수정안을 세웠습니다.

AI는 구현 초안·오류 가설·반복 실험을 가속했고, 저는 문제 정의·평가 기준·실험 실행·주장 채택과 철회를 책임졌습니다. 제가 보여주고 싶은 AI 역량은 답을 그럴듯하게 만드는 능력이 아니라, 틀릴 수 있는 구조를 먼저 찾고 근거·한계·운영 trade-off까지 공개하는 능력입니다.
