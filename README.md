# AI Validation Portfolio

> 높은 정확도를 믿지 않고, AI의 답을 운영 가능한 판단으로 바꿉니다.

SK하이닉스 AI Hackathon 2026 지원을 위해 정리한 검증 중심 포트폴리오입니다. 결과가 좋아 보일 때도 데이터 누수, 평가 기준, 불확실성, 실제 사용 여부를 다시 확인했습니다. 유리한 수치보다 **재현되는 주장과 철회할 줄 아는 판단**을 남기는 것이 이 저장소의 목적입니다.

## 한눈에 보는 세 가지 사례

### 1. SECOM — 정확도 93.3%인데 불량을 한 건도 못 찾았다

- 데이터: UCI SECOM, 1,567건 × 590개 센서, 불량 104건(6.64%)
- 고정 holdout: 314건, 불량 21건
- 기본 임계값 0.5: TP 0 / FN 21
- 학습 OOF에서만 정한 임계값 0.0717: TP 19 / FN 2 / FP 117 / TN 176
- Recall 90.5%, Precision 14.0%, 재검사율 43.3%, PR-AUC 0.238

핵심은 Recall 하나를 자랑하는 것이 아닙니다. 불량 미탐을 줄이는 대신 검사 대상이 43.3%로 늘어나는 trade-off를 함께 공개합니다. 실제 비용이 주어지면 임계값을 다시 결정해야 합니다.

기존 분석에서 “상위 80개 센서가 전체보다 우수하다”고 보았지만, 특성 순위를 각 fold의 학습 부분에서만 계산한 3회 반복 5-fold CV에서는 평균 PR-AUC가 80개 0.137, 전체 0.168이었습니다. 기존 주장은 선택 편향의 영향을 받았다고 보고 철회했습니다.

### 2. sLLM vs RAG — 정답보다 평가 누수를 먼저 확인했다

Qwen2.5-0.5B LoRA와 RAG를 8개 합성 Q&A, 5개 질문으로 비교했습니다. RAG가 외부 문서의 값과 업데이트를 회수했지만, 일부 질문은 학습 Q&A 및 검색 문서와 사실상 동일했습니다. 따라서 일반 성능 우월성은 주장하지 않습니다. 이 실험이 보여준 것은 제한된 exact-match 조건에서의 외부 사실 회수 가능성과 평가 설계의 한계입니다.

### 3. Agent Study Coach — 안전장치가 자기 보고서를 근거로 착각했다

13개 원본 단위를 60개 chunk로 색인하고, LangGraph가 검색과 퀴즈 도구를 선택하도록 구현했습니다. 그러나 “노트 밖 질문이면 근거 없음”을 검증하는 질문이 색인된 Day 3 보고서 안에도 들어가 있었습니다. 에이전트는 원래 학습노트가 아니라 자기 평가 보고서를 검색해 답했습니다. 해결 방향은 지식 corpus와 평가·보고서 corpus의 물리적 분리입니다. 실제 사용자 활용이나 학습 향상은 측정하지 않았습니다.

## 재현 방법

Python 3.11+ 환경을 권장합니다.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python src/revalidate_secom.py
python src/revalidate_secom.py --feature-audit
```

스크립트가 공식 UCI ZIP을 내려받고 SHA-256을 확인한 뒤 `results/`에 JSON·CSV를 생성합니다. `--feature-audit`는 Random Forest 반복 학습으로 시간이 더 걸립니다.

## 구조


## 데이터 출처

UCI Machine Learning Repository, *SECOM* (DOI: [10.24432/C54305](https://doi.org/10.24432/C54305)). 원본 데이터는 저장소에 재배포하지 않고 공식 주소에서 내려받습니다.

## 해석 범위

- holdout의 불량은 21건뿐이며 수치를 생산 환경 성능으로 일반화할 수 없습니다.
- 임계값은 운영 비용 함수가 아니라 학습 OOF 불량 점수의 30백분위수로 정한 시연용 operating point입니다.
- RAG/Agent 사례는 소규모 교육용 구현입니다. 독립 평가셋과 실제 사용자 성과가 없습니다.
- 저장소에는 개인정보, API 키, 지원서 원본을 포함하지 않습니다.
